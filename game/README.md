# おしりまでがイモムシです — MVP 試作

`docs/caterpillar_trap_game_plan.md` の **11章「MVPの仕様」** を Godot 4 で実装したものです。
目的は「長い体を這わせる操作感」と「体の後ろを狙う理不尽な罠」が面白いかを確かめることで、アートと音は仮のものです。

## 動かし方

1. Godot **4.4 以降**（4.4.1 で動作確認）で `game/project.godot` を開き、F5 で実行します。
2. タイトル画面でステージを選びます。

| ステージ | 内容 | 企画書との対応 |
|---|---|---|
| 試験場（MVP-0） | 段差・樹皮の壁・ガラスと樹皮の天井・幅2/4/6/8節の隙間・崩れる床・トゲの穴 | 11.2 |
| α はじめての葉っぱ | 這う・登る・首伸ばし → #06 紙の葉っぱ橋 → #22変種 ハマグリの扉 | 11.3 / ステージ1 |
| β おしりは見えない | #17 頭センサーのギロチン → #19 しっぽ離しスイッチ → #16 背後のハサミムシ | 11.3 / ステージ2 |
| γ 橋になれ | #01 定員オーバー橋 → #07 書き割り床 → #29 つっかえ棒 | 11.3 / ステージ3 |

### 操作

- **スマホ**：画面の下65%のどこでも指を置いてドラッグ（フローティングスティック）。小さく引くと低速、大きく引くと標準速度。指を離すと止まります。右下の「↩」を押している間は来た道を後ずさりします。
- **PC**：マウスでドラッグ（タッチとして扱われます）、または 矢印キー / WASD。Shift で低速、X か Backspace で後ずさり、R でリトライ。
- 上部バー：↻ リトライ / DBG（軌跡・支え・節番号の表示）/ ⚙（パラメータ調整。user://tuning.cfg に保存）/ ≡ メニュー。

### ルール（企画書 5章）

- 胴体は頭の通った道を正確になぞります。
- **支持ルール**：頭側の空中の節は4節まで、支えに挟まれた空中の区間（橋渡し）は8節まで、尻尾側のぶら下がりは8節まで。破ると落下（簡易ロープ物理）します。
- 首を伸ばせる限界で押し続けると、約1秒で手が滑って落ちます（自分から落ちたいとき用）。
- 床はどの素材でも支えになります。壁と天井は樹皮・葉だけがつかめて、ガラスと石はつかめません。
- 即死（赤・トゲ）／切断（銀の刃・ハサミ。6節より短くなると失敗）／押しつぶし（大玉）／挟まれ（ハマグリ）。
- ゴールは「全身」が巣穴に入ったときだけ成立します。

## テスト

```sh
godot --headless --path game --import            # 初回のみ（クラス名のキャッシュを作る）
godot --headless --path game --script res://tests/run_tests.gd
```

`tests/run_tests.gd` は入力を自動で与えるシナリオテストです（35項目）。罠ごとに「素直に進むと失敗する」ことと「企画書どおりの攻略で突破できる」ことを確かめます。

スクリーンショット（画面のある環境、または `xvfb-run` 経由）：

```sh
godot --path game --resolution 720x1280 --script res://tests/screenshot.gd -- 1 /tmp/alpha - - 120,300
```

## 分析用ログ

失敗・切断・リトライ・クリアを `user://mvp_log.jsonl` に1行1件の JSON で追記します（企画書 11.4 の指標 T2・T3・T6・T7 の集計用）。
記録する項目：ステージ、死因、部位、節番号、座標、リスポーンからの経過時間。

- Linux：`~/.local/share/godot/app_userdata/おしりまでがイモムシです (MVP)/`
- Windows：`%APPDATA%\Godot\app_userdata\おしりまでがイモムシです (MVP)\`
- Android：アプリのデータ領域（`adb` で取り出す）

## Android / iOS への書き出し

縦画面固定、描画方式は Compatibility（OpenGL ES 3）です。`export_presets.cfg` に Android のプリセットがあります。

| 項目 | 値 |
|---|---|
| パッケージ名 | `com.imomushi.oshirimade` |
| バージョン | 0.1.0-mvp（versionCode 1） |
| CPU | arm64-v8a、armeabi-v7a |
| 署名 | デバッグ用キーストア（テスト配布用。ストア公開には使えない） |
| 書き出し方式 | テンプレート APK（Gradle ビルドは使わない） |

書き出し：`GODOT=/path/to/godot game/tools/build_android.sh` → `build/oshiri-mvp-debug.apk`。
事前準備（エクスポートテンプレート、JDK、Android SDK、エディタ設定）はスクリプト冒頭のコメントに書いてあります。

**端末へのインストール**：APK を端末にコピーして開く（「提供元不明のアプリ」の許可が必要）、または `adb install build/oshiri-mvp-debug.apk`。

- デバッグ署名は書き出した環境ごとに異なります。別の環境で書き出した APK で上書きインストールすると署名の不一致で失敗するので、先にアンインストールしてください。
- ストアに出す場合は、リリース用のキーストアを作って `--export-release` で書き出します（キーストアはリポジトリに入れないこと）。
- **iOS**：macOS と Xcode、Apple Developer Program への登録が必要です（企画書 10.4）。

## ファイル構成

```
scripts/core/     params.gd（調整値）  trail.gd（軌跡）  support_rule.gd（支持ルール）
                  world.gd / solid.gd（矩形地形と決定的な当たり判定）  caterpillar.gd（体・状態・描画）
scripts/traps/    罠（1ファイル1種類）
scripts/stages/   ステージ（地形と罠の配置）
scripts/game/     game.gd（進行・失敗演出）  camera_rig.gd  hud.gd  touch_stick.gd  tuning_panel.gd ほか
tests/            run_tests.gd（シナリオテスト）  screenshot.gd
```
